# Contract: the `python -m alfabeta` command

A single command with subcommands. The global option `--home <dir>` always goes before the subcommand
(`python -m alfabeta --home <dir> plan --student sample`); it is the folder of student configurations
and, if not given, it is `~/.alfabeta`. If that folder does not exist, the command stops and says so (it
is not created silently).

Every subcommand that acts on a student receives `--student <id>`, which is resolved once on entry
and not looked up again. Machine output goes to stdout as JSON; messages for people go to
stderr. No message shows student data: paths relative to the student's root (the absolute path of the
root is never shown, because the Google Drive for desktop one carries the account's email address) and
abbreviated opaque ids.

| Subcommand | What it does | Writes to | Output | Codes |
|---|---|---|---|---|
| `lock take --student <id> --mode interactive\|scheduled\|unattended` | Starts a run: stores in the lock its `mode`, its start time, the (empty) list of collected classes and an opaque run identifier, which it returns; the skill passes it in `ALFABETA_RUN` to every following command (inline, `ALFABETA_RUN=<id> uv run …`, because each tool call is a new shell). On a local home: takes with `fcntl.flock`, in a watcher process, the student's lock and the Mac's browser lock (a fixed path on the Mac, `~/.alfabeta/.browser.lock`, shared by all students regardless of `--home`). On a Drive-state-folder home (`--mode unattended`, or a Mac session working on a pulled home): the student's lock is the lease of research R19 — a lock file in the state folder, created only if absent, renewed by every subcommand (Drive's conditional update), taken over after `lock_idle_minutes`; the token route takes no browser lock. The watcher (or the lease) holds until `lock release` or until `lock_idle_minutes` pass without any subcommand renewing it; then it releases and writes a `stopped` line with reason `idle` | `data/lock` or the Drive state-folder lease; `~/.alfabeta/.browser.lock` on the Mac | JSON `{ok, run}` | 0 · 1 with reason `lock_busy` or `invalid_config` (`[sync]` not valid); in both cases it writes its own log line and the skill does not call `log stop` afterwards |
| `lock release --student <id>` | Releases both locks and ends the watcher, only if they belong to the run in `ALFABETA_RUN` | `data/lock` | JSON `{ok}` | 0 |
| `lock renew --student <id>` | Renews the lock and does nothing else; the other subcommands already renew; the skill calls it only during long waits (polling a long capture, building and uploading a book) | nothing | JSON `{ok}` | 0 · 1 if the lock is not held |
| `log stop --student <id> --reason <r>` | Writes the `stopped` line of a run halted before `apply` (`session_expired`, `challenge`, `unexpected_ui`, `timeout`, `drive_not_mounted`, `lock_busy`, `lock_not_held`, `invalid_config`) and releases the locks if they belong to the run in `ALFABETA_RUN` | `data/log.jsonl` | JSON `{ok}` | 0 · 1 if the reason is not in the list |
| `log notebook --student <id> --topic "Tema NN - <title>" --result created\|unchanged\|failed\|disabled [--reason <text>] [--shares <invited>,<already>,<failed>]` | Writes the line for a book's notebook step (constitution VII: the failure of an output shows in the log); `--reason` mandatory with `failed`; `--shares` gives the counts of the sharing step over `notebook.share_with` (FR-011b), never the addresses | `data/log.jsonl` | JSON `{ok}` | 0 · 1 if `--reason` is missing with `failed` or the result is not in the list |
| `config check --student <id>` | Validates the configuration against the template and checks that the Drive root exists and is not «Mi unidad» (My Drive), and that no mirror is the root, inside it, contains it or is «Mi unidad»; a mirror that is not mounted is a warning, not a problem (FR-011a) | nothing | JSON `{ok, problems:[{key, reason}]}` | 0 valid · 1 invalid (names the key, never the value) |
| `downloads collect --student <id> [--wait N]` | Moves from the downloads folder (`[downloads] folder`) to `data/` the captures and the attachments requested by the last plan, and records in the lock the classes whose captures it collects. It only collects captures of the run in progress: those carrying its `run` (in the name `alfabeta-capture-<run>-<class>-<stamp>.json` and in the `run` field); one from another run, or from another student, is ignored. An attachment matches by its expected name or that name with the ` (<n>)` suffix the browser adds, and only if it was created after the plan; two attachments with the same expected name never go in the same batch (the plan splits them into batches and the skill collects after each one), so each file has a single owner; it ignores everything else (including a file with that name older than the plan) and `.crdownload` files; it verifies they are complete | `data/` | JSON `{collected:[…], pending:[…]}` | 0 · 1 if any is missing after waiting |
| `plan --student <id> [--subject <folder>]…` | Compares sources, state and decisions; with `--subject` (repeatable), only those subjects; without it, the classes whose captures `downloads collect` collected since the last `lock take` (the lock's list). Exits with 1 and reason `invalid_config` if the `captured_at` instant of a capture falls outside September–August of `school_year` | `data/plan.json` | Plan JSON: `downloads` (url, expected_name, batch), `pending_decisions`, `changes` | 0 · 1 school year that does not match the captures |
| `decisions propose --student <id> --file <json>` | Records Claude's proposals (`class_link`, `topic_match`, `item_match`, `detected_exam`, `dismissed_candidate`: an exam candidate that Claude judges announces none, with the item as origin) with `reason` and `confidence` (`high`, `medium`, `low`). A proposal for a `(type, origin)` that already has a non-superseded decision writes nothing (a `rejected` one can be proposed again only if its origin shows a modification after the rejection or, for `topic_match`, if its title changed or a book topic appeared in the Drive after the rejection). A `detected_exam` or `dismissed_candidate` whose `origin_hash` no longer matches the text of its origin can be proposed again and leaves the previous one `superseded`, unless it has an `exam_correction` | `data/decisions.json` | JSON with what was recorded and what was ignored | 0 · 1 if a proposal does not fit the contract |
| `decisions confirm --student <id> --type <t> --origin <id> [--reject]` | Confirms or rejects a proposal. A `detected_exam` is not rejected (it is discarded with `correct --discard`); `--reject` on one exits with 1 | `data/decisions.json` | JSON | 0 · 1 if it does not exist |
| `decisions correct --student <id> --origin <id> (--date YYYY-MM-DD \| --category <c> \| --discard)` | Corrects a detected exam (the `detected_exam` of that origin) with an `exam_correction` decision, which prevails in the following runs | `data/decisions.json` | JSON | 0 · 1 if it does not exist |
| `decisions change --student <id> --type <t> --origin <id> --target <folder>` | Changes a confirmed or rejected match: the previous one becomes `superseded` and the next `apply` moves the replicas | `data/decisions.json` | JSON | 0 · 1 if it does not exist |
| `apply --student <id> [--subject <folder>]…` | Reads the run mode from the lock (`lock take --mode`; no `--mode` flag of its own), so an `unattended` run skips the master and the mirrors (below). Takes from the captures, with the same scope as `plan`, what is new and what changed; regardless of the scope, recomputes the target of every replica of the student (moves those a decision changed) and the agenda from the state. If a `stop` capture with `class` was collected, that class is left unapplied and the result is `partial` with its reason. Recomputes the targets with the decisions in force in `data/decisions.json` at that moment (including those confirmed after `plan`); places replicas, notes and gradings; keeps previous versions; deletes from `data/` the collected attachments once placed or checked identical; updates state and log only if they change; regenerates the agenda only if it changes, and uploads it only if its hash differs from the one the data home records as last written (FR-036); ends by bringing the mirrors up to date as `mirror` does — **except in an `unattended` run (the lock's mode), where it writes neither the master nor the mirrors**, only the agenda through spec 004's connection (FR-036) | Drive folder, mirrors, `data/` (none of the master or mirrors in an unattended run) | Summary for the family (stderr), with how many mirrors are up to date and how many failed, and counters JSON with `result` = `ok` or `partial` (stdout) | 0 complete or partial (`result` says which; a partial one from a session expiring midway carries `reason`) · 1 stopped (Drive not available, lock not held) |
| `mirror --student <id>` | Brings each folder in `drive.mirrors` up to date from the root, one-way: `rsync -rlt --exclude .DS_Store <root>/ <mirror>/`, without `--delete` (measured on the family Mac, 2026-10-26). A mirror that is not mounted or fails is counted and the rest go on. `apply` and `book place` run it at their end; the skill calls it alone only to repair a mirror | the mirrors | JSON `{up_to_date, failed:[{index, reason}]}` (a mirror is named by its position in the list, never by its path) | 0 · 1 if any mirror failed |
| `agenda --student <id>` | Regenerates `agenda.json` and `agenda.md` from the state and the decisions, only if they change | Drive folder | JSON `{written:[…]}` (empty if nothing changed); the text for people to stderr | 0 |
| `book place --student <id> --subject <folder> --topic "Tema NN - <title>" --origin <dir>` | Places the result of a book provider in `<school-year>/<subject>/<topic>/<book>/`, where `<topic>` is the existing folder whose name contains `Tema NN - `, whatever its `YYYYMMDD - ` prefix, or a new `<today> - Tema NN - <title>` if there is none, and `<book>` is the subject's `book` value, with hash and previous version, brings the mirrors up to date as `mirror` does, and adds its line to the log (instant, source, topic, placed or unchanged, mirrors) | Drive folder, mirrors, `data/` | JSON with what was placed | 0 · 1 if the subject has no book or `--topic` does not have the form `Tema NN - <title>` |
| `runner read --student <id>` | The unattended runner's whole run (User Story 7), in its image only: takes the lease in the data home (research R19; `lock take --mode unattended`), loads the newest secret version. If there is none, it stops `session_expired` against a sentinel version `none`, so the family is told once that they must seed the vault (and a later run while there is still none repeats `none`, exit 0, no new notice). If the newest version is the one whose last run already stopped, it stops with that reason, exit 0, no new notice. Otherwise it reads, by the token route (read-only API calls) or the web route («Tareas pendientes», «Sin entregar», their details and the `recheck` items behind the browser guard of research R18), then `plan`, `apply` (unattended, from the lock) (no master, no mirrors) and `agenda` on the same home, uploads the agenda through spec 004's connection only if its hash changed, stores the renewed secret as a new version only if it changed and destroys the older ones, and releases the lease. A stopped run stores no new version | The data home (`captures/`, state, log), the agenda in Drive through spec 004's connection, the secret | JSON `{ok, result, reason, session_version}` | 0 `ok`; 1 `stopped`/`partial` the first time a `(reason, version)` appears (the project's alert policy notifies on exit 1); 0 `stopped` repeating a `(reason, version)` already logged (no new notice); 0 and silent on `lock_busy` (a Mac session legitimately holds the lease — not a failure, no notice) and inside a `challenge` cooldown |
| `runner session login --student <id>` | On a computer with a screen, takes the lease first (so a running `runner read` cannot overwrite the result, M7): for the token route, runs the embedded-setup sign-in and stores the resulting sign-in token as a new secret version; for the web route, starts the runner's Chromium with a fresh profile and no automation attached, the family signs in by hand to the school account (the command never reads, types or stores a password), and once the Classroom home shows it stores the profile's storage state as a new version, deletes the local profile and releases the lease. Prints only the version number. Which route it seeds comes from `runner.route`, fixed by the spike | The secret; the lease | JSON `{ok, version}` | 0 · 1 if the sign-in does not complete, the account is not `classroom.account`, or the lease is held (nothing stored) |
| `runner home pull --student <id>` / `runner home push --student <id>` | For a family session on the Mac with a student whose data home is the runner's (research R19): `pull` takes the lease in the Drive state folder (the same lease `runner read` takes; `lock_busy` if held), copies the student's folder (configuration and `data/`) to a local `--home` and records the run; the usual subcommands then run with that local `--home` and each renews the lease; `push` writes back what changed only if the run still holds the lease (the lease generation is unchanged — fencing), regenerates and uploads the agenda per FR-036, then releases the lease. If the lease was lost (a long session past `lock_idle_minutes`, H4), `push` writes nothing, exits 1, and the session must re-`pull` and re-apply. The skills and the `decisions`/`book place` paths MUST wrap their work in `pull`/`push` for a `runner.enabled` student (H3), so the Drive state folder stays the only writable copy (FR-035) | The state-folder lease; the local copy; on `push`, the state folder | JSON `{ok, run}` / `{ok, written}` | 0 · 1 `lock_busy` on `pull`; `push` without the lease (nothing written) |
| `guardrail [--staged \| --all \| --history]` | Looks for personal data in the staged change, in the whole repository or, with `--history`, in `git log --all -p` (what is published) | nothing | findings `file:line: detector`; notice on stderr if there are no local configurations for the name detectors | 0 clean (also `--staged` with no files to check, with a notice on stderr) · 1 finding · 2 `--all` checked no file · 3 blind detector |
| `anonymize <input> <output>` | Generates a synthetic page: keeps the structure and the allowed interface labels and invents everything else | `<output>` | path written | 0 · 1 if any text from the input survives outside the allowed list |
| `sandbox prepare [--student <id>]` | Requires an explicit `--home` (never `~/.alfabeta`). Creates in `--home` an invented student (`sample` if `--student` is not given), its own Drive folder `drive/<student>/`, the empty downloads folder every student of that home shares, the captures from `tests/fixtures/` in `sandbox-captures/` and the invented attachments in `sandbox-attachments/` (both outside the downloads), the confirmed class links and a `detected_exam` proposal (what Claude contributes in a real run) | `--home` | paths created | 0 |
| `sandbox download --student <id> (--captures \| [--batch N])` | Requires an explicit `--home`. With `--captures`, copies to the downloads folder those in `sandbox-captures/` with the current `run` (`ALFABETA_RUN`) in their name and their field, as the extractor would leave them; without it, copies from `sandbox-attachments/` to the downloads folder the attachments the last plan requests (that batch), with the current time as creation date, as Claude would when downloading them | sandbox downloads folder | paths copied | 0 · 1 if the plan requests one that does not exist in `sandbox-attachments/` |

Common rules:

- Without `--student` where it is needed: argparse code 2 and usage message.
- `lock *` and `log stop` only read `[sync]` and do not check the Drive, so a stop can be
  logged even if the rest of the configuration or the Drive fails; if `[sync]` is not
  valid, `lock take` exits with 1 and writes the `stopped` line with `invalid_config` itself.
  The other subcommands validate the whole configuration on entry. When `plan` or `apply` stop
  (school year that does not match, Drive not mounted), they write their own `stopped` line and release
  the locks; the skill does not call `log stop` afterwards.
- `apply` with no changes writes nothing to the Drive folder, to its mirrors or to the state (FR-025).
- `apply`, `plan`, `downloads collect`, `decisions *`, `agenda`, `book place`, `mirror` and `log notebook` check that
  the student's lock is held by the run in `ALFABETA_RUN` and renew it; if it is not
  held or belongs to another run, they exit with 1.
- Each class's captures are kept up to `kept_captures`; `apply` deletes only the oldest
  ones from `data/captures/`, never anything from the Drive folder. That deletion is part of the run's
  own records (FR-025).
